# Как всё устроено

**Главное в Layero — пять понятий: организация, проект, окружение, сборка и основной адрес.** Ниже — что значит каждое и как они связаны, а в конце — чем статический сайт отличается от приложения с сервером.

## Организация

Организация владеет проектами, базами данных и балансом. Подписка Pro тоже оформляется на организацию, а не на человека.

При первом входе вы выбираете имя аккаунта, и под этим именем создаётся ваша
личная организация. Для работы с коллегами есть командные организации — см.
[Организации](../team/organizations.md).

Переключатель организаций — в панели. Списки проектов, репозиториев и сборок
показывают только то, что относится к выбранной организации.

## Проект

Проект — это один сайт или одно приложение. Он получает адрес
`https://<проект>.layero.app`; точный адрес видно в панели и в выводе CLI.

Код попадает в проект одним из способов:

- из подключённого репозитория — каждый пуш запускает сборку;
- из папки — командой `layero deploy` или загрузкой в панели;
- готовыми файлами от AI-агента — инструментом MCP `publish_site`.

Проект с репозиторием принимает и загрузки из папки. Они попадают в отдельное
окружение `cli` и не трогают основной адрес, пока вы сами не опубликуете их
флагом `--prod`.

## Окружение

Окружение — это адрес проекта со своей историей сборок. Обычно окружение соответствует ветке: пуш в новую ветку создаёт окружение, и по его адресу открывается превью этой ветки.

У проекта без репозитория одно окружение — `cli`: в него идут все загрузки из
папки. Подробнее — [Окружения и превью](../deploys/environments.md).

## Сборка

Каждый пуш и каждая загрузка запускают сборку. Платформа определяет
фреймворк, ставит зависимости, собирает проект и сохраняет результат.
Статусы сборки в панели:

| Статус | Что значит |
|---|---|
| «В очереди» | ждёт свободного сборщика |
| «Сборка» | идёт сборка |
| «Готов» | открывается по адресу окружения |
| «Ошибка» | сборка упала; причину покажет лог или `npx layero@latest diagnose` |
| «Отменён» | сборку остановили |

Чем и как собирается проект — [Фреймворки](../build/frameworks.md),
[Версии Node.js и Python](../build/runtime-versions.md) и
[`layero.json`](../build/layero-json.md).

## Основной адрес

По основному адресу `<проект>.layero.app` и по вашим доменам открывается одна и та же сборка. Обычно это последняя удачная сборка основной ветки, а у проекта без
репозитория — последняя загрузка из папки.

Любую готовую сборку можно сделать основной: она откроется сразу, без пересборки. Откат устроен так же: прошлая сборка снова становится основной.
В панели это кнопка «Откатить», в CLI — [`layero rollback`](../deploys/rollback.md)
и [`layero promote`](../deploys/rollback.md).

## Статический сайт и приложение с сервером

- **Статический сайт.** После сборки остаются файлы: HTML, JavaScript, CSS.
  Их раздают серверы Layero, и никакой процесс не запускается. Это самый быстрый вариант: страница отдаётся сразу, ждать запуска процесса не нужно.
- **Приложение с сервером.** Next.js с серверным рендерингом, серверы на
  Node.js и Python, Streamlit, Gradio, Flask. Оно работает как отдельный
  процесс: просыпается по первому запросу и засыпает, когда к нему не
  обращаются. См. [Runtime-приложения](../runtime/overview.md).

## Плашка «Сделано на Layero»

Внизу статического сайта показывается тонкая полоса «Сделано на Layero». Она
не перекрывает содержимое и подбирает цвет под низ страницы. Для этого
платформа добавляет в каждый HTML-файл перед `</body>` одну строку:

```html
<script defer src="/_layero/footer-<хеш>.js" data-layero-footer></script>
```

В репозиторий ничего не пишется: строка есть только в файлах, которые
раздаёт платформа.

**Где плашки нет:**

- в HTML без `</body>` и в файлах не в UTF-8;
- в файлах подтверждения прав для Яндекс Вебмастера, Google Search Console
  и Bing;
- в `node_modules` и в папках, имя которых начинается с точки;
- на страницах, которые отдаёт приложение с сервером. У фронтенда
  фуллстек-проекта плашка есть.

**Как убрать.** На тарифе Pro: панель → проект → «Настройки» →
«Layero Label» → «Выкл». Там же можно выбрать цвет полосы. Изменение
применится со следующей сборки. Агент выключает плашку инструментом MCP
`project_settings` с параметром `badge: false`. Если организация вернётся на
Free, плашка появится снова — см. [Тарифы](../billing/plans.md).
