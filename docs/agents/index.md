# Как AI-агент работает с Layero

**Агент публикует и обслуживает сайт сам — от вас нужен один клик, чтобы
подтвердить вход.** Claude Code, Cursor, Codex и любой агент, который умеет
запускать команды или подключать MCP, работают с Layero одинаково.

Как это выглядит в чате:

```
Вы:     опубликуй этот лендинг на Layero
Агент:  Откройте https://app.layero.ru/cli?code=ABCD-1234 и подтвердите вход.
Агент:  Готово: https://my-landing.layero.app
```

Дальше можно попросить «поменяй кнопку на красную» — агент поправит код и
опубликует снова по тому же адресу.

Всё, что агенту нужно знать, собрано в навыке `layero` — см.
[Навык layero](./skill.md). Как подключить навык и MCP к вашему клиенту —
[Подключить агента](./install.md).

## Три пути

От ситуации зависит, что делает агент.

### Подключён репозиторий

Проект связан с репозиторием на GitHub, GitVerse, GitLab, GitFlic или
SourceCraft. Тогда публикация — это `git push`:

- пуш в ветку даёт превью по отдельному адресу;
- пуш в основную ветку (обычно `main`) обновляет сайт.

Агент коммитит и пушит, больше ничего запускать не нужно. Если репозиторий
есть, а проекта на Layero ещё нет, агент создаёт его сам:

```bash
npx layero@latest projects create --repo github:acme/site
```

Или инструментом MCP `import_repo`. Человек может сделать то же в панели:
**«Новый проект» → «Импорт из репозитория»**. Подробнее —
[Подключение репозитория](../deploys/git-providers.md).

### Есть папка с кодом

Репозитория нет, или подключать его не хочется:

```bash
npx layero@latest deploy --dry-run --json   # как соберётся, ничего не загружает
npx layero@latest deploy --json
```

CLI упакует папку, и платформа соберёт её у себя: сборщик на машине агента не
нужен, только Node.js 20 или новее для `npx`. Готовые файлы с `index.html`
агент может опубликовать и без CLI — инструментом MCP `publish_site`.

Как CLI разговаривает с агентом — события, коды ошибок, адрес сайта — на
странице [JSON-события CLI](./json-events.md).

**Если проект определился неверно.** В первый раз агент публикует без
`layero.json`. Упала сборка или сервер опубликовался как статика — агент
правит одно поле по таблице симптомов на странице
[`layero.json`](../build/layero-json.md) и не повторяет публикацию с той же
ошибкой.

### Сайт уже на Layero

Сайт опубликован, и нужно разобраться, что с ним, или что-то настроить. Для
этого у агента есть MCP: `diagnose_deploy` объясняет упавшую сборку,
`deploy_logs` даёт логи, `rollback` откатывает, `connect_domain` подключает домен, `check_domain` проверяет его, `env_vars` меняет переменные окружения,
`site_analytics` показывает трафик, `data_api_*` работают с базой. То же
умеет CLI: `layero diagnose`, `layero logs`, `layero rollback`,
`layero domains`, `layero env`. Полный список — [Инструменты MCP](./mcp-tools.md).

### Как выбрать путь

| Вопрос | Да | Нет |
|---|---|---|
| У проекта есть подключённый репозиторий? | `git push` | следующий вопрос |
| Есть папка с исходниками или готовыми файлами? | `npx layero@latest deploy --json` или `publish_site` | следующий вопрос |
| Сайт уже на Layero, нужно разобраться или настроить? | инструменты MCP или команды CLI | спросить человека, чего он хочет |

Есть ли у проекта репозиторий, агент видит в ответе `site_status` или
`my_projects`.

## Вход

Агенту не нужно просить человека запустить `layero login`: команда
`layero deploy` сама начинает вход и печатает ссылку. Агент показывает её в
чате и ждёт — человек открывает ссылку, входит и возвращается в разговор.
Браузер может быть на другом устройстве.

В CI и фоновых задачах, где некому подтвердить вход, нужен токен в переменной `LAYERO_TOKEN`. Как его выпустить — [Подключить агента](./install.md#layero_token-для-ci).

## Сайт без аккаунта

Аккаунта ещё нет или человек отошёл от компьютера:

```bash
npx layero@latest deploy --claim --yes --json
```

Платформа публикует временный сайт на час по случайному адресу, закрытому от
поисковиков. Вместе с адресом агент получает ссылку `claim_url` и передаёт её
человеку: забрать сайт в свой аккаунт может только человек. Так публикуются
только статические сайты и SPA — приложению с сервером нужен аккаунт.

Без флага `--claim` и без токена CLI просит войти. Публиковать без аккаунта
агент может, только если человек об этом попросил или согласился.

## Чего агент не делает

- **Не создаёт репозиторий ради публикации.** Нет репозитория — публикует
  папку, а не делает `git init`.
- **Не ставит CLI глобально.** `npm i -g layero` в песочнице агента часто не
  работает — всегда `npx layero@latest`.
- **Не составляет адрес сайта сам.** Адрес — только из ответа платформы: поле
  `url` события `ready` у CLI или ответ `publish_site` и `site_status` у MCP.
  Адрес, собранный по имени проекта, может оказаться чужим или пустым.
- **Не заменяет живой сайт без ведома человека.** У проекта без репозитория
  каждый запуск `layero deploy` сразу виден посетителям — превью у такого проекта
  нет, и флаг `--branch` его не даст. Инструменты MCP, которые меняют сайт,
  клиент выполняет только после подтверждения — см.
  [Инструменты MCP](./mcp-tools.md#что-требует-согласия-человека).
