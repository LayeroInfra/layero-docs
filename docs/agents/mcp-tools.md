# Инструменты MCP

**MCP-сервер Layero даёт агенту доступ к проектам, сборкам, доменам и базе.**
Адрес сервера — `https://mcp.layero.ru/mcp`, имя в настройках клиента —
`layero`. Как подключить, описано на странице [Подключить агента](./install.md). Ниже собрано, что делает каждый инструмент.

{/* Имена инструментов сверяет с живым сервером ../mcp/check-tool-names.py:
    снятые имена (compose_landing и прочие) здесь недопустимы. */}

Значок ⚠️ — инструмент может менять сайт, проект или доступ: всегда или только с частью параметров. Например, `env_vars` меняет переменные, только когда записывает их.

## Аккаунт и проекты

| Инструмент | Что делает |
|---|---|
| `whoami` | Кто подключён: имя аккаунта, почта, число проектов. |
| `my_projects` | Проекты с адресами и источником кода — репозиторий или загрузка из папки. Параметр `repo` оставляет проекты одного репозитория. |
| `list_sources` | Провайдеры репозиториев (GitHub, GitVerse, GitLab, GitFlic, SourceCraft) и что из них подключено у организации. |
| `import_repo` ⚠️ | Создать проект из репозитория и запустить первую сборку. Приложение в подпапке — параметр `root_directory`, например `apps/web`. Провайдер не подключён — в ответе ссылка на панель: токен провайдера подключает человек. Репозиторий уже привязан — в ответе список его проектов. |
| `project_create` ⚠️ | Пустой проект без репозитория — адрес под будущую публикацию. |
| `project_settings` ⚠️ | Прочитать или поменять настройки сборки: папку приложения, команды установки и сборки, папку результата, тип проекта, плашку «Сделано на Layero». Показывает, откуда взято каждое значение. |

## Сайт и сборки

| Инструмент | Что делает |
|---|---|
| `site_status` | Состояние сайта: последняя сборка, адрес, репозиторий и ветка. Отличает ответ самого сайта от страницы платформы. Параметр `path` проверяет конкретный адрес на сайте, `wait_s` ждёт конца идущей сборки. |
| `list_environments` | Окружения проекта — ветки с адресами и состоянием последней сборки. |
| `list_deploys` | История сборок: статус, источник, время в очереди и длительность. |
| `deploy_logs` | Логи сборки и приложения. Шумные строки установки пакетов по умолчанию скрыты. |
| `diagnose_deploy` | Почему упала сборка: разбор лога, следующий шаг и чем собирали — фреймворк, команды, папка результата, версия Node.js. |
| `retry_deploy` ⚠️ | Перезапустить сборку. С `redeploy=true` пересобирает последний коммит без пуша. |
| `cancel_deploy` ⚠️ | Остановить идущую сборку. |
| `rollback` ⚠️ | Вернуть на основной адрес прошлую сборку. |
| `download_source` | Ссылка на ZIP с исходниками загруженной сборки; живёт 5 минут, файлов `.env*` в архиве нет. У сборки из репозитория — ссылка на коммит. |
| `publish_site` ⚠️ | Опубликовать готовые файлы с `index.html` без CLI: до 200 файлов, до 8 МБ всего и до 2 МБ на файл. Проекта нет — создаёт. `publish_landing` — старое имя того же инструмента. |
| `env_vars` ⚠️ | Прочитать, задать или удалить переменные окружения. |

## Домены

| Инструмент | Что делает |
|---|---|
| `list_domains` | Домены проекта и их состояние. |
| `connect_domain` ⚠️ | Подключить свой домен — возвращает DNS-записи, которые нужно создать. |
| `check_domain` | Проверить, заработал ли домен: DNS и сертификат. |

## Содержимое сайта

| Инструмент | Что делает |
|---|---|
| `read_site` | Прочитать страницу опубликованного сайта — текст и разметку. |
| `site_screenshot` | Снимок страницы сайта. |
| `site_issues` | Что чинить на сайте: битые ссылки, метатеги, доступность — с адресом каждой проблемы. |
| `refactor_site` | Предложить правку разметки. Возвращает изменения, файлы не трогает. |
| `check_copy` | Вычитать русский текст: типографика и редакционные правила. |
| `check_rules` | Проверить сайт по [правилам Layero](https://layero.ru/rules) против фишинга: сбор чужих паролей и данных карт, поддельные предупреждения, приманки с призами. |
| `check_performance` | Замерить скорость сайта: Core Web Vitals и Lighthouse. |

## Data API

| Инструмент | Что делает |
|---|---|
| `data_api_status` | Включён ли Data API у базы проекта и по какому адресу. |
| `data_api_methods` | Таблицы и функции, доступные по API, и кому они открыты. |
| `data_api_grant` ⚠️ | Открыть или закрыть доступ к таблице или функции для роли. |
| `data_api_keys` ⚠️ | Выпустить или отозвать ключи. |
| `data_api_origins` ⚠️ | Сайты, которым разрешены запросы к базе из браузера. |
| `data_api_buckets` ⚠️ | Бакеты для файлов: список и создание. Создание требует токена с правом `admin`. |
| `data_api_auth` ⚠️ | Вход пользователей приложения: способы, провайдеры, адрес возврата, имя отправителя писем. Ключи провайдеров задаёт человек — в панели или командой `layero data auth provider set`. |
| `data_api_probe` | Пробный запрос к таблице или функции: проверить доступ и ответ. Записи откатывает, данные не меняет. |

## Документация

| Инструмент | Что делает |
|---|---|
| `search_docs` | Поиск по docs.layero.ru. |
| `report_docs_issue` | Сообщить нам об ошибке в документации, из-за которой агент потерял время. Данные аккаунта в отчёт не попадают. |

## Что требует согласия человека

Клиент (Claude Code, Cursor, Codex) выполняет инструменты с ⚠️ только после подтверждения человека. Остальные только читают, и клиент вызывает их без
вопросов. Иногда клиент спрашивает и про `data_api_probe` или
`report_docs_issue`: они не помечены как «только чтение», хотя проекты не
меняют.

Перед `rollback`, `publish_site`, записью в `env_vars`, `data_api_grant` и
`data_api_keys` агент называет человеку, что именно изменится, и ждёт ответа —
даже если клиент подтверждения не требует.

## Вход

Без входа работают `search_docs`, `report_docs_issue`, `check_copy` и
`refactor_site`: подключите сервер и спрашивайте про платформу сразу.

Остальным инструментам нужен аккаунт. Клиент с входом по OAuth при первом
таком вызове сам откроет браузер, и вам останется подтвердить вход. Для CI и сред без браузера нужен заголовок `Authorization: Bearer $LAYERO_TOKEN`; как выпустить токен — [Подключить агента](./install.md#layero_token-для-ci). Публиковать без
аккаунта умеет только CLI: `npx layero@latest deploy --claim`.

## Один проект или только чтение

Подключение можно ограничить прямо в адресе сервера:

```
https://mcp.layero.ru/mcp?project=<slug>
https://mcp.layero.ru/mcp?project=<slug>&read_only=true
```

- `project=<slug>` — инструменты работают только с этим проектом: вызов с другим проектом получит отказ.
- `read_only=true` — инструменты, которые меняют сайт или проект, отвечают отказом. Это удобно для агента, которому нужно только разобраться в проблеме. Отправить отчёт об ошибке в документации при этом можно.

Адрес с параметрами укажите в поле `url` в настройках клиента.
