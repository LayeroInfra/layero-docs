# Инструменты MCP

MCP-сервер Layero: `https://mcp.layero.ru/mcp`, транспорт Streamable HTTP,
имя в конфигах клиентов `layero`. Как подключить, описано на странице
[Подключить агента](./install.md); здесь — что сервер умеет, по одной строке
на каждый инструмент.

## Аккаунт

| Инструмент | Что делает |
|---|---|
| `whoami` | Кто подключён: пользователь, организация, срок токена. |
| `my_projects` | Список проектов с адресами и источником (репозиторий или CLI). |

## Сайт и деплой

| Инструмент | Что делает |
|---|---|
| `site_status` | Состояние сайта: последний деплой, адрес, окружения. |
| `list_deploys` | История сборок проекта. |
| `deploy_logs` | Логи сборки и приложения. |
| `diagnose_deploy` | Почему упала сборка — с разбором лога и следующим шагом. |
| `retry_deploy` ⚠️ | Перезапустить упавшую сборку. |
| `cancel_deploy` ⚠️ | Отменить идущую сборку. |
| `rollback` ⚠️ | Откатить продакшен на прошлую сборку. |
| `publish_site` ⚠️ | Опубликовать готовую статику (папку с `index.html`) без CLI; создаёт проект, если его нет. `publish_landing` — устаревший алиас `publish_site`. |
| `env_vars` ⚠️ | Прочитать, задать или удалить переменные окружения проекта. |

## Домены

| Инструмент | Что делает |
|---|---|
| `list_domains` | Домены проекта и их состояние. |
| `connect_domain` ⚠️ | Подключить свой домен: возвращает DNS-записи, которые нужно создать. |
| `check_domain` | Проверить, заработал ли домен: DNS и сертификат. |

## Содержимое сайта

| Инструмент | Что делает |
|---|---|
| `read_site` | Прочитать страницу опубликованного сайта как текст и разметку. |
| `site_screenshot` | Снимок страницы сайта. |
| `site_issues` | Что чинить на сайте: битые ссылки, метатеги, доступность. |
| `refactor_site` | Предложить правку разметки — возвращает патч, файлы не трогает. |
| `check_copy` | Вычитать русский текст по редакционным правилам Layero. |
| `check_performance` | Замерить скорость сайта: Core Web Vitals, Lighthouse. |

## Аналитика

| Инструмент | Что делает |
|---|---|
| `connect_analytics` ⚠️ | Подключить Яндекс Метрику к проекту. |
| `site_analytics` | Трафик сайта за период. |

## Data API

| Инструмент | Что делает |
|---|---|
| `data_api_status` | Включён ли Data API у базы проекта и его адрес. |
| `data_api_methods` | Методы (таблицы и функции) и кто к ним допущен. |
| `data_api_grant` ⚠️ | Открыть или закрыть доступ к методу для роли. |
| `data_api_keys` ⚠️ | Выпустить или отозвать ключи Data API. |
| `data_api_origins` ⚠️ | Сайты, которым разрешены запросы из браузера (CORS). |
| `data_api_probe` | Пробный вызов метода — проверить, что доступ и ответ такие, как ожидалось. |

## Документация

| Инструмент | Что делает |
|---|---|
| `search_docs` | Поиск по docs.layero.ru; единственный инструмент, который работает без входа. |

## Какие инструменты требуют согласия человека

Инструменты, помеченные ⚠️, **меняют** сайт, проект или доступ — сервер
объявляет их без `readOnlyHint`, и клиент (Claude Code, Cursor, Codex)
спрашивает подтверждение перед вызовом. Остальные только читают, и клиент
вызывает их без вопросов.

Правило для агента: перед `rollback`, `publish_site`, `env_vars` с записью,
`data_api_grant` и `data_api_keys` назвать человеку, что именно изменится,
и дождаться ответа — даже если клиент подтверждения не требует.

## Вход

Сервер отвечает на `search_docs` без входа; всё остальное требует
аккаунта Layero. Клиент, поддерживающий OAuth, откроет браузер сам при
первом вызове. Для CI и сред без браузера — заголовок
`Authorization: Bearer $LAYERO_TOKEN`; как выпустить токен — на странице
[Подключить агента](./install.md#layero_token-для-ci).

## Параметры адреса: `project` и `read_only`

Область действия сервера можно сузить прямо в адресе подключения:

```
https://mcp.layero.ru/mcp?project=<slug>
https://mcp.layero.ru/mcp?project=<slug>&read_only=true
```

- `project=<slug>` — все инструменты работают только с этим проектом;
  `my_projects` вернёт его одного, а вызов с другим проектом получит отказ.
- `read_only=true` — инструменты с ⚠️ не объявляются вовсе. Удобно для
  агента, который должен только диагностировать.

Параметры задаются в поле `url` конфига клиента; отдельного механизма не
нужно.
