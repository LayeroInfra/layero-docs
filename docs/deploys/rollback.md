# Откат и выбор сборки

**Любую готовую сборку, которая ещё хранится, можно сделать основной за секунды, без пересборки.**
Откат — частный случай: основной снова становится прошлая сборка. Это
работает одинаково для статических сайтов и для приложений с сервером.

## Откатить на прошлую сборку

**В панели:** нажмите «Откатить» на странице проекта и подтвердите в окне «Откатить основной адрес?».

**В CLI:**

```bash
npx layero@latest rollback
```

Команда находит прошлую готовую сборку основной ветки, показывает план и после подтверждения открывает её по основному адресу.

Второй откат подряд ничего не меняет: прошлая сборка уже на основном адресе, и команда ответит кодом `rollback_noop`. Чтобы вернуть более новую сборку, выложите её командой `promote`.

| Флаг | Что делает |
|---|---|
| `--deploy <id или sha>` | откатить на конкретную сборку, а не на прошлую |
| `--branch <ветка>` | откатить другую ветку, а не основную |
| `--project <id или слаг>` | проект, если команда запущена не из его папки |
| `-y`, `--yes` | не спрашивать подтверждения |

```bash
npx layero@latest rollback --deploy a3f9c2b
npx layero@latest rollback --branch staging
```

## Выложить любую сборку

**В панели:** в списке деплоев — кружок «Сделать основной» у нужной сборки, на странице деплоя — «Сделать активным».

**В CLI:**

```bash
npx layero@latest deploys list          # найти нужную сборку
npx layero@latest promote a3f9c2b       # сделать её основной
```

`promote` принимает id сборки или начало хеша коммита. Ищет он среди
сборок основной ветки, поэтому сборку другой ветки или загрузку из папки
укажите вместе с веткой:

```bash
npx layero@latest promote a3f9c2b --branch cli
```

Без аргумента `promote` берёт последнюю готовую сборку ветки из `--branch`, а если ветка не указана — окружения `cli`. У проекта с репозиторием это загрузка из папки, а не сборка `main`. Чтобы выложить последнюю сборку основной ветки, укажите ветку:

```bash
npx layero@latest promote --branch main
```

Перед выкладкой команда показывает план — проект, основной адрес, какую сборку выкладывает и какая открывается по нему сейчас — и просит подтвердить.
Флаг `-y` его пропускает; в CI и у агента команда не спрашивает. В режиме
JSON приходит событие `promoted`.

У проекта с репозиторием собрать загрузку из папки и сразу выложить её на основной адрес можно одной командой `layero deploy --prod` — см. [«Из папки через CLI»](./deploy.md).

## Ограничения

- **Выложить можно только готовую сборку**, которая ещё хранится.
  Упавшие, отменённые и удалённые по сроку хранения сборки не подходят —
  см. [«Хранение сборок»](./retention.md).
- **Свои домены** показывают то же, что основной адрес, и меняются вместе
  с ним.
- **Пуш в основную ветку** снова сделает основной новую сборку, если
  включена автоматическая публикация. Чтобы следующий пуш не перезаписал откат, выключите её — см. [«Окружения и превью»](./environments.md#публиковать-пуши-автоматически-или-вручную).
