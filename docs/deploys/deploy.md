# Из папки через CLI

**`layero deploy` загружает папку на Layero, платформа собирает её и
публикует.** Репозиторий не нужен.

```bash
cd my-site
npx layero@latest deploy
```

Посмотреть план без загрузки и без входа:

```bash
npx layero@latest deploy --dry-run
```

План показывает фреймворк, команду сборки, папку с результатом, откуда взято
каждое значение и заменит ли загрузка живой сайт.

## Что происходит

1. CLI смотрит на папку и печатает, как её понял. Это подсказка: фреймворк,
   команду сборки и папку с результатом платформа определяет сама по
   загруженным файлам — см. [«Фреймворки»](../build/frameworks.md).
2. Упаковывает папку, пропуская файлы по правилам ниже, и загружает архив.
3. Платформа собирает проект. Лог сборки идёт прямо в терминал.
4. CLI ждёт, пока сайт начнёт отвечать (до 90 секунд), и печатает его адрес.

Первая загрузка из папки создаёт проект и записывает его в
`.layero/project.json`. Следующие загрузки из этой папки идут в тот же
проект.

Если вы ещё не вошли, `layero deploy` сам покажет ссылку для входа — см.
[«Установка и вход»](../cli/install.md).

## Куда попадает загрузка

- **Проект без репозитория.** Каждая загрузка сразу заменяет сайт по
  основному адресу. Загрузить версию, которая не станет живой, нельзя.
- **Проект с подключённым репозиторием.** Загрузка попадает в отдельное
  окружение `cli` с адресом `<проект>-cli.layero.app` и основной адрес не
  трогает. Чтобы выложить её на основной адрес, добавьте `--prod`.

Выбрать ветку для загрузки нельзя: CLI отклоняет флаг `--branch` с кодом `branch_unsupported`. Превью веток дают пуши в подключённый репозиторий —
см. [«Подключение репозитория»](./git-providers.md).

Точный адрес берите из вывода CLI (поле `url` события `ready`), а не
собирайте по шаблону.

## Флаги

| Флаг | Что делает |
|---|---|
| `--dry-run` | показать план сборки и выйти. Ничего не загружает, вход не нужен |
| `--prod` | только для проекта с репозиторием: выложить загрузку на основной адрес |
| `--promote` | результат тот же, что у `--prod`, только основной адрес после сборки переключает сам CLI отдельным запросом |
| `-y`, `--yes` | не задавать вопросов, в том числе не спрашивать подтверждения для `--prod` |
| `-t`, `--type <тип>` | задать фреймворк или тип приложения вручную — список значений на странице [«Фреймворки»](../build/frameworks.md#задать-фреймворк-вручную) |
| `--root <папка>` | монорепозиторий: папка приложения, например `apps/web`. Запоминается в проекте |
| `--prebuilt [папка]` | отправить готовую сборку, не собирая её на платформе |
| `--name <имя>` | имя нового проекта |
| `--address <метка>` | адрес нового проекта: `inbox` → `inbox.layero.app` |
| `--org <слаг>` | организация для нового проекта. По умолчанию — личная |
| `--project <id или слаг>` | загрузить в существующий проект, не глядя на `.layero/project.json` |
| `--db <база>` | подключить базу организации до сборки, чтобы первая сборка уже получила адрес и ключ Data API |
| `--claim` | опубликовать без аккаунта, см. ниже |
| `--confirm-repeated-failure` | продолжить, хотя последние сборки падают с одной и той же ошибкой |
| `--json` | печатать события JSON, см. ниже |

### `--prebuilt`: готовая сборка

Без папки берётся первая существующая из `dist`, `build`, `public`, `out`,
`_site`, `.output/public`, `docs/.vitepress/dist`, `.vitepress/dist`.

:::warning[`--prebuilt` не смотрит в `.gitignore`]
Для готовой сборки правила `.gitignore` и `.layeroignore` не применяются.
`layero deploy --prebuilt .` в корне проекта опубликует всё, что там лежит,
включая черновики, спрятанные через `.gitignore`. Файлы `.env*`, `.git` и
`node_modules` исключены и здесь, но папку для `--prebuilt` всё равно
указывайте явно.
:::

### `--claim`: без аккаунта

С `--claim` CLI публикует временный сайт на час и печатает ссылку, по которой сайт забирают в аккаунт. Подходят только статические сайты и одностраничные приложения: на приложение с сервером CLI ответит ошибкой `claim_static_only`. Адрес случайный,
поисковики сайт не индексируют. Без `--claim` и без входа `deploy` попросит
войти.

## Что не отправляется

CLI пропускает файлы по правилам `.gitignore` и `.layeroignore` (синтаксис
тот же) и по своему списку:

```
node_modules  .git  .svn  .hg
dist  build  .next  .nuxt  .output  .cache  .turbo  .vercel  .netlify
.env  .env.*  *.log  .DS_Store  Thumbs.db  .layero
.gitignore  .layeroignore
```

Результаты сборки (`dist`, `build`, `.next`) загружать не нужно: проект
соберётся на платформе. Lock-файлы отправляются всегда, даже если их скрыл `.gitignore`: по ним ставятся зависимости.

**Файлы `.env*`** не попадают в архив, даже если `.gitignore` их разрешает.
Если файл окружения нужен при сборке, верните его строкой с `!` в `.layeroignore`. Например, для `.env.production` с публичными переменными Vite:

```
!.env.production
```

Широкие правила вроде `!*` файлы окружения не возвращают. Секреты лучше
хранить в [переменных окружения проекта](../build/env-vars.md).

## Лимиты

- Архив загрузки — до 500 МБ.
- Сборка — до 30 минут, установка зависимостей — до 30 минут, выгрузка
  результата — до 10 минут, а всё вместе — до 40 минут.
- Память сборки — 4 ГБ.

Сборка идёт в изолированной среде: сборки разных проектов не видят друг друга. Не хватает лимитов — напишите в [поддержку](../support.md).

## Режим JSON для агентов и CI

С флагом `--json` или переменной `LAYERO_JSON=1` CLI печатает по одному
JSON-объекту на строку:

```jsonl
{"event":"detected","framework":"vite","build_cmd":"npm run build","output_dir":"dist","confident":true}
{"event":"packing","files":124,"bytes":2401234}
{"event":"deploy_started","deploy_id":"..."}
{"event":"build_log","line":"...","stream":"stdout"}
{"event":"ready","url":"https://my-site.layero.app/","dashboard_url":"https://app.layero.ru/projects/...","deploy_id":"..."}
```

В событии `ready` поле `url` — сам сайт, `dashboard_url` — страница проекта
в панели. Ошибка приходит событием `error` с кодом и готовым следующим
шагом в `next_action`.

Без флага режим JSON включается, когда CLI запущен внутри AI-агента — Claude
Code, Cursor, Aider и других, которые выставляют свою переменную окружения.
В CI и когда вывод идёт не в терминал, CLI печатает обычный текст и ничего не
спрашивает: `--prod` там выкладывает на основной адрес без подтверждения.

Все события и коды ошибок — [JSON-события CLI](../agents/json-events.md).
