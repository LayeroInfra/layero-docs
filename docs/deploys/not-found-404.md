# Страница 404 и SPA-fallback

Когда посетитель открывает URL, которого нет в вашей сборке, Layero
должен что-то ответить. Есть два правильных поведения — и они
противоположны:

- **Многостраничный статический сайт** (Next.js `output: 'export'`,
  Astro, Hugo, Eleventy, Jekyll…) обычно кладёт в сборку файл
  **`404.html`** и ждёт, что неизвестный адрес вернёт именно его — с
  HTTP-кодом **404**. Так поисковики (Яндекс, Google) понимают, что
  страницы нет.
- **SPA с клиентским роутингом** (React, Vue, Angular, Solid без
  пререндера) наоборот хочет, чтобы **любой** адрес отдавал
  `index.html` с кодом **200** — тогда приложение загрузится и его
  роутер сам покажет нужный экран (или свою 404-заглушку).

## Как Layero ищет файл по адресу

Прежде чем отдать 404 или SPA-fallback, Layero по очереди ищет в сборке
файл для адреса. Например, для `/docs/hello`:

1. файл ровно по адресу: `/docs/hello`;
2. страницу каталога: `/docs/hello/index.html`;
3. страницу с расширением: `/docs/hello.html`;
4. если ничего не нашлось, отдаёт страницу 404 или SPA-fallback, как
   описано ниже.

Шаг 3 нужен генераторам с «чистыми» адресами: VitePress с
`cleanUrls: true`, Astro с `build.format: 'file'`, Eleventy, если
страницы собираются в `имя.html`. Ссылка `/docs/hello` открывает
`docs/hello.html`, а не главную страницу или страницу 404.

Настраивать ничего не нужно. Уже выложенные деплои тоже открываются
по чистым адресам, пересобирать сайт не надо.

Layero пропускает шаг 3, если адрес заканчивается на `/` или в его
последней части есть точка (`/app.js`, `/logo.png`). Если в сборке есть
и `hello/index.html`, и `hello.html`, откроется `hello/index.html`:
шаг 2 идёт раньше шага 3.

## Поведение по умолчанию

Layero выбирает автоматически по содержимому сборки:

| В корне сборки есть `404.html`? | Неизвестный URL отдаёт |
|---|---|
| **Да** | `404.html` с кодом **404** |
| **Нет** | `index.html` с кодом **200** (SPA-fallback) |

Для большинства проектов делать ничего не нужно: Next export, Astro,
Hugo и подобные генераторы кладут `404.html` сами — и он начинает
отдаваться с правильным кодом. Vite/CRA-приложения `404.html` не
создают — и продолжают работать как SPA.

:::note
Сам файл `404.html` по прямому адресу (`/404.html`) всегда доступен с
кодом 200 — под 404 попадают только **неизвестные** URL.
:::

## Переопределение через `_redirects`

Если авто-определение вам не подходит, положите в корень сборки файл
**`_redirects`** (синтаксис Netlify) с catch-all правилом:

```
# Форсировать SPA-fallback, даже если 404.html присутствует:
/*   /index.html   200

# Или наоборот — явно включить свою страницу 404:
/*   /404.html     404
```

- `/* /index.html 200` — **всегда** отдавать `index.html` с кодом 200.
  Нужно приложениям с клиентским роутингом, которые при этом почему-то
  генерируют `404.html`.
- `/* /404.html 404` — отдавать указанную страницу с кодом 404. Путь
  может быть любым (`/not-found.html` и т.п.), файл должен лежать в
  сборке.

Правило должно идти **последним** в `_redirects` — обычные редиректы
(`301`/`302`) в том же файле продолжают работать как раньше.

## Проверка

```bash
curl -I https://<адрес-вашего-проекта>/страница-которой-нет
# HTTP/2 404      ← ожидаемо для статического сайта с 404.html
# HTTP/2 200      ← ожидаемо для SPA
```

Изменение вступает в силу со **следующим деплоем** — Layero определяет
страницу 404 в момент сборки.
