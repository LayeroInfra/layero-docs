# Переменные окружения

Env vars задаются в разделе проекта **«Переменные окружения»** в панели,
командой `layero env` или через API. Они доступны процессу сборки и попадают
в `process.env`. Изменения подхватит **следующая сборка**: уже опубликованная
версия сайта их не увидит.

## Где они применяются

Env vars подставляются в окружение **на стадии сборки** (этап `env`
в pipeline билдера, до `install`). Это значит, что фреймворки, которые
встраивают переменные в бандл (Vite, Next.js с `NEXT_PUBLIC_*`, CRA с
`REACT_APP_*`), увидят их и зашьют в артефакты.

Для **runtime-проектов** (SSR Next, Streamlit, Gradio) переменные
дополнительно прокидываются в окружение запущенного контейнера —
доступны в runtime через тот же `process.env` / `os.environ`.

## Безопасность

Значения шифруются в БД алгоритмом **AES-256-GCM** с уникальным nonce
на запись.

Ключ шифрования (`ENV_ENCRYPTION_KEY`) **в базе не хранится**: источник
правды — секрет-хранилище, откуда ключ попадает в окружение control-plane
при выкатке. Практический смысл — дамп базы сам по себе значений не
раскрывает: без ключа это шифротекст.

Ключ **никогда не попадает в ваши контейнеры** — ни в сборочный, ни в
runtime. Туда приезжают только расшифрованные значения тех переменных,
которые вы сами добавили этому проекту.

Сохранённое значение платформа не показывает — ни в панели, ни
в CLI, ни в API: видны только имя и длина, а у длинных значений — первые
символы.

## Что НЕ хранить

- **Никогда не коммитьте `.env*`** — `.env`, `.env.local` и т. п.
  попадают в встроенный denylist `layero deploy` и в любом случае не
  заливаются. Но если они окажутся в git-репо при GitHub-flow — Layero
  склонирует их на стадии `clone`.
- **Production-секреты не должны попадать в `NEXT_PUBLIC_*` /
  `VITE_*` / `REACT_APP_*`** — эти префиксы означают «попасть в
  клиентский бандл». Используйте их только для публичных значений
  (например, public API endpoints, токены аналитики и т. п.).

## CLI и API

Из терминала — командой `layero env`. `set` добавляет и меняет только
названные переменные, остальные остаются как были:

```bash
npx layero@latest env list
npx layero@latest env set API_URL=https://api.example.com
npx layero@latest env unset API_URL
```

:::warning[API заменяет весь набор]
`PUT` в API записывает переданный набор **целиком**: ключ, которого нет
в запросе, будет удалён. Чтобы сохранить существующее значение, передайте
ключ со значением `null`. Для правки одной переменной надёжнее `layero env set`.
:::

```bash
curl -X PUT https://api.layero.ru/projects/{id}/env \
  -H "Authorization: Bearer $LAYERO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"vars": {"API_URL": "https://api.example.com", "SECRET_KEY": null}}'
```

Здесь `API_URL` получит новое значение, `SECRET_KEY` останется прежним,
а все остальные переменные проекта будут удалены.
