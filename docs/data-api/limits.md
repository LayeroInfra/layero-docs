# Чего нет

:::info[Бета-версия]

Data API работает в бета-версии и доступен на тарифе Pro. Чего ждать
от страниц, написано в [«Что такое Data API»](./index.md).

:::

Неподдержанное отвечает отказом с именем возможности, а не молчаливой
заглушкой. Молчаливое расхождение дороже отсутствия — «работает,
но не так» всплывает у посетителя, а не у разработчика.

## Возможности, которых нет

| Чего нет | Что делать |
|---|---|
| **Realtime** — подписки на изменения | опрос по интервалу |
| **Edge Functions** — исполнение вашего кода у нас | логика в функциях базы; наружу — [HTTP из SQL](./outbound.md) (`net.http_post`) |
| **Входящие вебхуки** — адрес, который принимает запрос чужого сервиса | свой сервер на Layero принимает вебхук и вызывает функцию; варианты — в [HTTP из SQL](./outbound.md#входящие-вебхуки--их-нет) |
| `/auth/v1/admin/*` | управление пользователями — своими функциями в схеме `api` |
| смена почты, SMS, корпоративный SSO | —; второй фактор есть: приложение-аутентификатор (TOTP), `supabase.auth.mfa.*` |
| RS256/JWKS | токены подписаны HS256 секретом базы |
| преобразования картинок, возобновляемая загрузка, S3-протокол | готовьте файл на своей стороне; загрузка и раздача работают |

⚠️ «Edge Functions нет» **не** значит «наружу нельзя». Уведомления в Telegram,
вебхуки и вызовы чужих API делает функция базы через `net.http_post` — см.
[HTTP из SQL](./outbound.md). Нет именно исполнения вашего кода на нашей стороне.

## Границы, о которых лучше знать заранее

| Что | Значение |
|---|---|
| Одновременных запросов к одной базе | общая база — 4 (по 2 на каждый из двух входов), и они общие у Data API и вашего сервера; выделенная — 20 % потолка соединений кластера, не меньше 4. Это же число показывает `layero db list` (`data_api_concurrent`). Сверх — очередь, затем отказ `db_too_busy` |
| Запросов к одной базе за сутки | Free — 50 000, Pro — 1 000 000; сверх — отказ `quota_exceeded` (429) до 03:00 по Москве |
| Пользователей входа у одной базы | Free — 10 000, Pro — 100 000; сверх — новые регистрации закрыты, вошедшие работают |
| Файл в хранилище | до 50 МБ на любом тарифе |
| Место под файлы одной базы | Free — 1 ГБ, Pro — до 100 ГБ |
| Баз на организацию | общая — одна, выделенных — сколько нужно; см. [«Лимиты» баз](../database/limits.md) |
| Источников приёма у базы | 50 |

Запросы считаются все: к таблицам, функциям, файлам и HTTP из SQL.
Сайты и подключение к базе по протоколу Postgres суточный предел
не трогает.

Отдельный код `db_too_busy` означает «перегружены вы», а не «перегружена
платформа»: соседние базы при этом работают.

## Клиент

Свой пакет — `@layero/data`. Он тонкий: вызов функций базы через шлюз, без обёртки над таблицами.

```bash
npm i @layero/data
```

```js
import { createClient } from "@layero/data";

const db = createClient({
  url: import.meta.env.VITE_LAYERO_DATA_URL,   // https://data.layero.ru/<база>
  key: import.meta.env.VITE_LAYERO_DATA_KEY,   // pk_live_…
});

const menu = await db.rpc("menu");
```

⚠️ Версия 0.x: HTTP-контракт ещё меняется, пин версии в проде обязателен.

Для таблиц, фильтров и входа пользователей берите `@supabase/supabase-js` —
контракт совместим, и он умеет всё, чего `@layero/data` пока не умеет.
Обойтись можно и без пакетов, запрос уместится в несколько строк:

```js
const call = (fn, args) =>
  fetch(`${import.meta.env.VITE_LAYERO_DATA_URL}/rest/v1/rpc/${fn}`, {
    method: "POST",
    headers: { "content-type": "application/json",
               apikey: import.meta.env.VITE_LAYERO_DATA_KEY },
    body: JSON.stringify(args),
  }).then((r) => r.json());
```
