# Файлы и состояние

**Всё, что приложение с сервером пишет на диск, пропадает при перезапуске: после новой сборки и после долгого простоя.**
Данные храните в базе, файлы — в хранилище, сессии — в cookie или в базе.

## Почему диск временный

- После 48 часов без посетителей приложение снимается с сервера, и следующий запуск идёт из чистого образа — см.
  [«Запуск и простой»](./lifecycle.md). Записанное на диск не сохраняется.
- Каждая сборка запускается в новом контейнере с чистым диском. Не рассчитывайте, что файл доживёт до завтра, даже при постоянном трафике.

## Что не работает

- **SQLite с записью**: база проживёт только до перезапуска.
- **Файловые базы**: `node-persist`, `lowdb`, `nedb` и подобные.
- **Сессии в файлах**: `express-session` с FileStore, файловые сессии
  Flask и подобные.
- **Загрузки пользователей на диск**: файл пропадёт при перезапуске.

## Что работает

- **SQLite только для чтения**, если файл лежит в репозитории и попадает
  в образ.
- **Кеш в памяти приложения**, пока оно работает.
- **Временные файлы в `/tmp`** — каталог в памяти, до 64 МБ — для данных одного запроса.

## Где хранить

| Что | Где |
|---|---|
| Данные | [база данных Layero](../database/index.md) — строку подключения платформа передаёт в переменную `LAYERO_DATABASE_URL` |
| Загруженные файлы | [хранилище файлов](../data-api/storage.md) Data API |
| Сессии | токен в cookie или таблица сессий в базе |
| Кеш между перезапусками | таблица в базе |
