# Резервные копии

**У общей базы копии включены с момента создания, у выделенной это платная опция.** Всё о копиях — на странице базы, в разделе «Резервные копии»: вверху видно, включены ли они, ниже — расписание, срок хранения, стоимость и список готовых копий.

Общая база копируется раз в сутки, копии хранятся 7 дней. Выключить копии можно, но тогда вернуть удалённые данные будет не из чего.

## Общая база

| Что | Как устроено |
|---|---|
| По умолчанию | включены |
| Как часто | раз в сутки, по умолчанию в 03:00 по Москве. Час можно сменить |
| Сколько хранятся | от 1 до 7 дней, выбираете вы |
| Где лежат | в отдельном хранилище, не на сервере базы |
| Место | квоту базы не занимают |
| Цена | входят в тариф |

Час копии и срок хранения меняются кнопкой «Изменить настройки». Если копии выключили, включить их снова — «Резервные копии» → «Включить».

## Выделенная база

Копии выделенной базы — **платная опция**, по умолчанию выключенная.

1. «Резервные копии» → «Включить».
2. Выберите, сколько копий хранить: от 1 до 14. Копия снимается раз
   в сутки ночью, самая старая вытесняется новой.
3. Окно покажет расчёт до подтверждения: база, копии и итог в месяц.

Цена копий зависит от диска и числа копий — примеры на странице
[«Тарификация»](./pricing.md#резервные-копии-выделенной-базы). Стоимость копий списывается
с баланса вместе с платой за базу.

Отключить копии можно в любой момент: уже снятые копии при этом
не удаляются.

## Сделать копию вручную

Кнопка «Сделать копию» вверху раздела снимает внеочередную копию — например,
перед рискованной миграцией. Копия появится в списке со статусом
«снимается…», а когда будет готова — с размером и кнопками.

## Восстановить

У готовой копии — кнопка «Восстановить».

⚠️ Восстановление идёт **в эту же базу, поверх текущих данных**, на момент
копии. Всё, что появилось после копии, будет потеряно. Восстановить базу
на произвольный момент нельзя.

- **Общая база** восстанавливается без остановки. Пока идёт восстановление,
  приложение может увидеть данные в промежуточном состоянии.
- **Выделенная база** на время восстановления останавливается: обычно это
  несколько минут, приложение в это время не подключится. Права ролей
  и доступ по Data API платформа вернёт сама.

Когда всё закончится, панель скажет: «Данные восстановлены на момент копии».

Если нужно достать из копии одну таблицу, а не откатывать базу целиком,
[скачайте копию](#скачать-копию) и разверните её локально.

## Скачать копию

Копию скачивают кнопкой со стрелкой в строке готовой копии.

У общей базы файл — обычный дамп PostgreSQL в формате `pg_dump -Fc`.
Его можно развернуть на любом сервере PostgreSQL, в том числе за
пределами Layero, командой `pg_restore`:

```bash
pg_restore --no-owner --no-privileges -d postgresql://localhost/restored backup.dump
```

Так же можно переехать с Layero или держать копию у себя на всякий случай.

У выделенной базы файл — снимок диска целиком. Его размер равен размеру
диска базы, а не объёму данных: у базы на 8 ГБ с данными на 60 МБ файл
будет весить 8 ГБ. Чтобы получить файл размером с данные,
[снимите свой дамп](#свой-дамп).

### Свой дамп

Снять дамп своими средствами можно и у общей, и у выделенной базы —
обычным `pg_dump` по строке подключения из панели. Перед этим проверьте
три вещи.

1. **Версия `pg_dump` не ниже версии сервера.** У общей базы это PostgreSQL 18, у выделенной — версия, выбранная при заказе. `pg_dump` более ранней версии выгружать отказывается: `aborting because of server version mismatch`. Версию покажет `pg_dump --version`.
2. **Ваш адрес — в списке разрешённых.** Без этого сервер ответит
   `no authentication method is found`. Как добавить адрес — в разделе
   [«Кого пускать к базе»](./connect.md#кого-пускать-к-базе).
3. **У клиента есть корневой сертификат.** Строка из панели требует
   `sslmode=verify-full`, и без корневого сертификата `pg_dump`
   откажет: `root certificate file "…/root.crt" does not exist`. Либо
   положите сертификат по
   [инструкции «Как включить verify-full»](./connect.md#как-включить-verify-full),
   либо допишите к строке `&sslrootcert=system`, и `pg_dump` возьмёт
   корневые сертификаты системы. В официальном Docker-образе `postgres`
   системных сертификатов нет, поэтому там кладите сертификат по инструкции.

Дальше — обычная выгрузка в SQL-файл:

```bash
pg_dump "postgresql://<роль>:<пароль>@db.layero.ru:5432/<база>?sslmode=verify-full&sslrootcert=system" -f backup.sql
```

Развернуть такой файл можно командой `psql -f backup.sql`.

У выделенной базы работают и архивные форматы, например `-Fc` для
`pg_restore`. У общей базы на архивные форматы (`-Fc`, `-Fd`, `-Ft`) и ключ `-C`
сервер отвечает `permission denied for table pg_db_role_setting`: эта служебная таблица общая для всех баз сервера и закрыта для клиентов. Если нужна копия общей базы в архивном формате, скачайте её из панели.

## Виды копий в списке

У общей базы в списке бывают копии двух видов:

| Вид | Что это |
|---|---|
| **Копия в хранилище** | выгружена с сервера и переживёт даже его потерю. Её можно восстановить и скачать |
| **Точка отката** | снимок, который хранится на самом сервере базы. Снимается за секунды и спасает от ошибки в данных, но не от потери сервера |

## Что будет с копиями при удалении базы

Удаление базы стирает и все её копии — сразу и безвозвратно. Если копия
может понадобиться, скачайте её **до** удаления.

Если база удаляется за неоплату, перед удалением мы пытаемся сохранить
копию, но не гарантируем этого — см.
[«Если на балансе не хватает денег»](./pricing.md#если-на-балансе-не-хватает-денег). Надёжнее не доводить до этого: включите копии и время от времени скачивайте свежую копию.
