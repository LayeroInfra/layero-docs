# HTTP-заголовки

**Свои HTTP-заголовки статического сайта задаются файлом `_headers` в корне
собранного сайта** — например `X-Frame-Options`, `Content-Security-Policy`
или `Referrer-Policy`. Синтаксис как у Netlify, с ограничениями, описанными ниже. Отдельной настройки в панели нет: файл лежит рядом с кодом.

Тег `<meta http-equiv>` не подойдёт: браузеры не принимают через него `X-Frame-Options`, эта политика работает только как настоящий заголовок ответа.

:::note[Приложения с сервером]
Всё это — про статические сайты. [Приложение с
сервером](../runtime/overview.md) (Next.js с серверной отрисовкой, Node.js,
Python) ставит заголовки само, в коде: `res.setHeader(...)`,
`headers()` в `next.config.js` и так далее.
:::

## Быстрый старт

Положите файл `_headers` (без расширения) в корень папки с результатом
сборки — рядом с `index.html`:

```text title="_headers"
/*
  X-Frame-Options: SAMEORIGIN
  Referrer-Policy: strict-origin-when-cross-origin
  X-Content-Type-Options: nosniff
```

После публикации заголовки будут отдаваться на всех страницах сайта.
Проверить:

```bash
curl -sI https://<адрес-проекта>/ | grep -i -E 'x-frame|referrer|x-content-type'
```

## Синтаксис

Файл состоит из блоков. Блок открывает строка пути: она начинается с `/` и стоит у левого края. Под ней идут строки с отступом вида `Имя-Заголовка: значение`.
Пустые строки и строки, начинающиеся с `#`, пропускаются.

```text title="_headers"
# Комментарий

/*
  X-Frame-Options: DENY

/about/
  X-Robots-Tag: noindex

/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

### Какие пути поддерживаются

| Шаблон | Что подходит | Пример |
|---|---|---|
| `/*` | все адреса сайта | весь сайт |
| точный путь | ровно этот адрес | `/about/`, `/index.html` |
| `/префикс/*` | все адреса внутри префикса | `/assets/*`, `/docs/*` |

Звёздочка в середине пути (`/foo/*/bar`) и подстановки вроде `/blog/:slug`
не поддерживаются: такой блок пропускается с предупреждением в логе сборки.

### Если подходят несколько блоков

Блоки применяются по порядку, и если один заголовок задан в нескольких подходящих блоках, **побеждает последний**. Поэтому общий блок `/*` ставят
первым, а уточнения — ниже:

```text title="_headers"
/*
  Cache-Control: public, max-age=0, must-revalidate

/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

Здесь `/assets/style.css` получит долгий кэш, а остальные адреса —
`must-revalidate`. Ваш `Cache-Control` заменяет значение платформы.

## Какие заголовки задать нельзя

Платформа не даёт задать:

- `Strict-Transport-Security`, `Public-Key-Pins`,
  `Public-Key-Pins-Report-Only`;
- `Set-Cookie`;
- служебные заголовки `X-Layero-*`.

Строки с ними пропускаются с предупреждением в логе сборки. Остальные заголовки разрешены. Для `Content-Security-Policy`, `Access-Control-Allow-Origin`, `Access-Control-Allow-Credentials` и `X-Frame-Options` лог добавит напоминание `replaces the platform default for this site — applied as written`: заголовок применится так, как вы его написали.

## Куда положить файл

`_headers` должен оказаться в корне папки с результатом сборки — той,
что публикуется (`outputDirectory` в настройках проекта или в
[`layero.json`](../build/layero-json.md)).

- Большинство генераторов копируют файлы из папки статики (`public/`,
  `static/`) как есть. Положите `_headers` туда — после сборки он окажется
  в корне.
- В монорепозитории — внутри папки приложения.

Если после публикации заголовков нет, почти всегда файл не попал в корень
папки с результатом.

## Ошибки в файле не роняют сборку

Неверные строки — путь без `/`, заголовок без `:`, неподдерживаемый
шаблон, запрещённое имя — пропускаются, верные применяются. Все замечания
попадают в лог сборки. Пустой или удалённый `_headers` снимает заданные
раньше правила: заголовки всегда соответствуют последней сборке.

Заголовки работают одинаково на адресе `layero.app` и на
[своём домене](./custom-domains.md).

## Переадресации

Переадресации по пути задаются соседним файлом `_redirects` — см.
[«Страница 404 и переадресации»](./not-found-404.md). Переадресацию
`www.site.ru → site.ru` он не делает: для неё при подключении домена
отметьте «Подключить также `www.…`» — см. [«Свой домен»](./custom-domains.md).
