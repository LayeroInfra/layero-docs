# Страница 404 и переадресации

**Если в корне сборки есть `404.html`, неизвестный адрес получает эту страницу
с кодом 404. Если нет — `index.html` с кодом 200, как нужно одностраничным
приложениям.** Обычно настраивать ничего не нужно, а для особых случаев есть
файл `_redirects`.

## Как Layero ищет файл по адресу

Для адреса `/docs/hello` Layero по очереди проверяет:

1. файл ровно по адресу: `/docs/hello`;
2. страницу папки: `/docs/hello/index.html`;
3. страницу с расширением: `/docs/hello.html`;
4. Если ничего не нашлось, Layero отдаёт страницу 404 или `index.html`, см. ниже.

Шаг 3 нужен генераторам с «чистыми» адресами: VitePress с
`cleanUrls: true`, Astro с `build.format: 'file'`, Eleventy, если страницы
собираются в `имя.html`. Ссылка `/docs/hello` откроет `docs/hello.html`.

Шаг 3 пропускается, если адрес заканчивается на `/` или в последней его
части есть точка (`/app.js`, `/logo.png`). Если в сборке есть и
`hello/index.html`, и `hello.html`, откроется `hello/index.html`.

## Что получает неизвестный адрес

| В корне сборки есть `404.html`? | Неизвестный адрес получает |
|---|---|
| да | `404.html` с кодом **404** |
| нет | `index.html` с кодом **200** |

Это подходит обоим видам сайтов:

- **Многостраничный сайт** (Next.js со статическим экспортом, Astro, Hugo,
  Eleventy) кладёт в сборку `404.html`, и неизвестный адрес получает
  настоящий код 404. Так поисковики понимают, что страницы нет.
- **Одностраничное приложение** (React, Vue, Angular без пререндера)
  `404.html` не создаёт. На любой адрес Layero отдаёт `index.html`, приложение загружается, и его роутер сам показывает нужный экран.

Сам `404.html` по прямому адресу `/404.html` открывается с кодом 200.

## Файл `_redirects`

Положите файл `_redirects` в корень папки с результатом сборки. Синтаксис как у Netlify: на каждой строке одно правило — «откуда», «куда» и код.

```text title="_redirects"
# Переадресация одного адреса, по умолчанию 301
/old-page   /new-page

# Временная переадресация
/sale       /promo      302

# Целый раздел: остаток адреса подставляется вместо :splat
/blog/*     /posts/:splat   301
```

- Код — `301` (по умолчанию) или `302`. В правиле для всех адресов можно ещё `200` и `404`, см. ниже.
- `*` допускается только в конце пути, остаток адреса подставляется вместо
  `:splat`.
- Правила проверяются сверху вниз, срабатывает первое подходящее. В `_headers` наоборот: там побеждает последний подходящий блок.
- Строки, начинающиеся с `#`, и пустые строки пропускаются.

Не поддерживаются: подстановки вроде `/blog/:slug`, `*` в середине пути и
другие коды ответа. Такие строки пропускаются с предупреждением в логе,
сборка не падает.

### Своя страница 404 или поведение SPA

Если выбор по наличию `404.html` не подходит, задайте его последней строкой
`_redirects`:

```text title="_redirects"
# Всегда отдавать index.html с кодом 200, даже если есть 404.html
/*   /index.html   200
```

```text title="_redirects"
# Отдавать свою страницу с кодом 404
/*   /not-found.html   404
```

Правило для всех адресов ставьте **последним**: иначе оно перехватит
переадресации, которые идут ниже.

Переадресацию `www.site.ru → site.ru` файл не делает, она настраивается
при подключении домена — см. [«Свой домен»](./custom-domains.md).

## Проверка

```bash
curl -I https://<адрес-проекта>/страница-которой-нет
# HTTP/2 404   — сайт с 404.html
# HTTP/2 200   — одностраничное приложение
```

Изменения заработают после следующей сборки: страницу 404 и правила Layero определяет при сборке.
