# Организации и команды

**Проекты, домены, базы данных и баланс в Layero принадлежат организации.**
Организации бывают двух видов: личная и команда. Переключатель организаций —
в левом верхнем углу панели.

## Личная организация

Личная организация создаётся при регистрации, у каждого человека она одна.
Удалить её нельзя.

- **На Free** в ней работаете только вы: пригласить участников нельзя.
- **На Pro** она становится командой: можно приглашать участников, назначать
  [роли](./roles.md) и настраивать доступ к проектам. Отдельную команду для
  этого создавать не нужно.

## Команда

Команда — отдельная организация со своими участниками, подпиской, балансом и
картой.

- Подписка принадлежит самой команде. Команда работает на своём Pro, а не на
  тарифе кого-то из участников.
- Все списания команды идут с её баланса. Карта команды пополняет только этот
  баланс и не связана с картой вашей личной организации.
- Оплату видят и меняют только [владельцы](./roles.md#оплата) команды.

Новую команду создают в переключателе: «Создать организацию». Pro оплачивается
сразу, бесплатного периода у новой команды нет.

## Участники

Пригласить участника: настройки организации → «Участники» → блок
«Пригласить участников». Укажите почту и [роль](./roles.md) и нажмите
«Пригласить».

Приглашение приходит письмом и действует 14 дней. Чтобы принять его, войдите
в Layero с той почтой, на которую оно пришло. Отозвать приглашение можно там
же, в «Участниках».

## Места

Место нужно каждому владельцу, кроме первого, и каждому разработчику. Первый
владелец входит в подписку команды. Гости бесплатны, и их число не
ограничено.

- Место стоит 990 ₽ в месяц. Оно всегда оплачивается помесячно, даже при
  годовом Pro.
- Все места продлеваются в один день — в то число месяца, когда началась
  подписка команды.
- Место, добавленное посреди месяца, сразу оплачивается с баланса команды за
  остаток до даты продления. За место, уже оплаченное в этом месяце, деньги второй раз не списываются.
- Снять можно только свободное место. Деньги за оставшиеся дни не
  возвращаются.
- Места принадлежат команде, а не человеку. Участник ушёл — его место остаётся свободным и продлевается, пока владелец не снимет это место.
- Пригласить разработчика или владельца и повысить гостя можно, только если
  есть свободное место. Приглашение на такую роль тоже занимает место.
- Кто был в команде до перехода на новые роли, занимает место бесплатно,
  пока остаётся в команде. Если сделать такого участника гостем, льгота
  пропадёт: вернуть участника в разработчики можно только на платное место.
  Повышение до владельца льготу сохраняет.

Места добавляют и снимают в «Участниках», в блоке «Платные места», или командой `npx layero@latest team seats` — см. [В CLI](#в-cli).

Если продление мест не оплачено, начинается льготный период той же длины,
что у Pro, — см. [Баланс и продление](../billing/lifecycle.md). После него доступ теряют разработчики сверх оплаченных мест, начиная с последних приглашённых: они остаются в команде, но не видят её проектов, пока продление не оплачено. Владельцев это не касается.

## Переключение между организациями

Переключатель запоминает выбранную организацию в браузере: после перезагрузки
страницы вы окажетесь в ней же. Панель показывает проекты, деплои и репозитории для импорта только выбранной организации.

## Перенос проекта в другую организацию

Проект → «Настройки» → «Передача проекта». Начните вводить название организации-получателя, панель подскажет подходящие. Заявка появится у получателя в
панели, в блоке «Входящие передачи проектов», и придёт ему письмом. Принять
или отклонить её можно там же. Пока заявка ждёт ответа, её можно снять
кнопкой «Отменить запрос».

- Если получатель отклонит заявку, отправителю придёт письмо, а в настройках
  проекта появится отметка об отказе.
- Заявка без ответа истекает через 14 дней. До этого вторую отправить нельзя: у проекта может быть только одна заявка.
- Проект принадлежит одной организации. После переноса у отправителя не остаётся доступа к проекту.
- Адрес проекта не меняется — ни поддомен на `layero.app`, ни свои домены.
  Вместе с проектом переезжают переменные окружения, деплои, настройки доступа
  и аналитика.

Если проект собирается из репозитория GitHub, а в новой организации ни у кого
нет доступа к нему на запись, связь с репозиторием разорвётся. Деплой не
пройдёт, пока её не восстановят на странице проекта.

## В CLI

Команды CLI работают в одной организации.

```bash
npx layero@latest orgs list
```

Показывает все организации, в которых вы состоите.

```bash
npx layero@latest deploy --org acme-team
```

Создаёт проект в команде `acme-team` при первом деплое из папки. Дальше
`deploy` в той же папке работает с этим проектом без `--org`. Если
организаций несколько, а `--org` не задан, CLI спросит, в какой создать
проект. С `--yes` он не спрашивает и создаёт проект в личной организации.

Участниками управляют командами `team`:

```bash
npx layero@latest team list --org acme-team
```

Показывает участников, их роли и доступ к проектам. Владелец видит ещё
приглашения и платные места.

```bash
npx layero@latest team seats --add 1 --org acme-team
npx layero@latest team invite anna@example.com --role developer --org acme-team
```

Добавляет место — остаток месяца сразу спишется с баланса команды — и
приглашает разработчика. Без свободного места разработчика или владельца
пригласить нельзя, гостя (`--role guest`) — можно.

```bash
npx layero@latest team access anna@example.com --all view --project shop=edit --org acme-team
```

Анна видит все проекты команды, а в `shop` может деплоить, менять домены и
переменные. Все команды — в [справочнике CLI](../cli/commands.md#участники-команды).

## GitHub

Чтобы команда собирала репозитории GitHub Organization и доступ не зависел от
одного человека, подключите [GitHub App](./github-app.md).
